# QTalk 1.1.1-beta — LAN2 — Windows x64

## English

1. Calls and Contacts filters paint their selected pill in the first layout pass. Each section keeps its own selection; subsequent selection changes still animate. Labels, translated counters, and display scaling determine the measured cell widths.
2. Unknown numbers keep the Position / Department / Company / Telegram information layout and placeholders. **Add contact** opens the inline editor with a snapshot of the displayed number. Cancel leaves the dial field intact; Save adds a local contact, handles normalized duplicates, and does not replace an active call's number. Notes require a saved contact.
3. Joined participants have a removal menu and confirmation for the original creator. The engine checks permission as well. Creator identity is carried separately from the current mixer host and survives handoff; a successor never inherits creator moderation. **Beta scope:** removal is available only when the original creator also owns the mixer. If the creator is a guest after migration, remote moderation is unavailable. If the creator leaves, no new moderator is appointed. Old snapshots without creator metadata initially treat their host as creator.
4. Graceful host exit prepares every peer, establishes replacement SIP/audio legs on the successor, and waits for every peer's readiness before committing. The old host retains its SIP legs until every peer acknowledges commit. Failures before commit abort the replacement and attempt to resume the retained original connections; another transfer waits for rollback acknowledgement. A missing commit acknowledgement leaves the decision in progress: keep QTalk open and retry leaving. Exit errors never silently become “end for everyone.”

### Host exit expectations and limits

- Every participant must use **1.1.1-beta LAN2** (shown in About). Old beta clients cannot join a LAN2 handoff; update all participants before leaving. Finish or cancel pending invitations first.
- Replacement legs use negotiated private IPv4 addresses and actual listening UDP SIP ports directly, with explicit unregistered LAN accounts on the same native core. They do not traverse the registered PBX. Normal calls and later ordinary invitations retain the registered account. No global default proxy, credentials, or firewall settings are changed by handoff.
- All remaining peers need direct TCP room-channel reachability and peer-to-peer UDP SIP/RTP reachability, plus capacity for temporary extra legs. Reaching the host alone is insufficient. Both receiving and sending native legs, RTP packet counters, and the successor mixer must be ready before commit; a blocked peer aborts before original-leg release. Windows may ask the user to allow QTalk on private networks. No firewall exception is added automatically; success on a particular topology requires a multi-PC check.
- SIP INFO advertises the LAN endpoint. Basic room state and graceful handoff do **not** require an Apps Script deployment. A PBX that blocks INFO can prevent discovery when no working optional directory service is configured. Older optional Apps Script deployments may not understand creator metadata after migration; SIP/LAN remains the primary beta path.
- Native audio may pause briefly while connections move between mixers. This is a rebridge, not a promise of uninterrupted audio. A three-person room leaves the remaining pair connected; its temporary mixer/UI can return to ordinary call mode.
- **Crash, power loss, forced termination, and loss of the host's network are not solved.** Audio is mixed on the host PC. There is no server mixer, durable election, or guaranteed recovery when that PC disappears. A partition during commit can leave a partial transfer that needs manual reconnection; do not assume timeout means everyone stayed on the old bridge.
- The LAN capability and negotiated transfer ID bind a handoff to an agreed room. SIP extension numbers and the anonymous directory are still a trusted-LAN model, not cryptographic user authentication. No remote “kick by claimed creator number” command is accepted.
- The installer uses the existing QTalk application identity and location: installing it upgrades that installation and reuses its local settings. It is not a separate side-by-side profile. The beta updater does not offer stable `1.1.1` as an update to this build; a numerically newer version such as `1.1.2` may still be offered.

### Safe diagnostic collection

LAN2 writes sanitized rolling diagnostics to `%LOCALAPPDATA%/QTalk/logs/qtalk-0.log` through `qtalk-3.log` (four files, about 256 KiB each; one final record can cross the threshold). Logging failure is nonfatal. Native verbose SIP logging is off by default.

After a colleague test, copy only these log files from each participating PC and record the approximate local time and extensions. The files contain UTC timestamps, LAN2 build marker, local/peer extensions, transfer correlation hashes, phases, readiness/acknowledgements and missing peers, native states/reason codes, admission decisions, direct IP:port and rollback/commit results. They exclude passwords, HA1, authorization, SIP bodies, raw exception messages, room capabilities and bearer transfer IDs. Logs still contain internal addresses/numbers: share them only with the intended support team. Do not collect credential/key databases, configuration files, the whole profile directory, or enable raw SIP traces for routine support.

### Three-PC smoke checklist (not performed during this build)

- [ ] On A/B/C, confirm About shows `1.1.1-beta (LAN2)`; configure three test SIP extensions on the same trusted LAN.
- [ ] On A, change Calls and Contacts filters independently, switch sections repeatedly, change language/scaling, and check there is no empty-pill frame or lost selection.
- [ ] Dial an unknown number. Check all four placeholders, prefilled creation, Cancel, Save, normalized duplicate handling, empty history/notes, and saving a draft while a different call becomes active.
- [ ] A creates a room with B and C. Only A sees removal menus on joined peers, none on self/pending invites. Cancel a removal, then confirm one; the other call must stay connected. Recreate the room.
- [ ] A leaves using Hang Up; repeat with application Exit. B and C should retain two-way audio after handoff, with no invented creator powers. Check mute/speaker/hold state and the resulting two-person call.
- [ ] Repeat with a fourth synthetic participant if available to check roster/creator preservation across a second handoff. While an invitation is pending, exit must refuse safely until it is finished or cancelled.
- [ ] Check a mixed old-beta/LAN2 room refuses handoff with an update-all error before replacement dialing. Check normal registered calls after a successful handoff, and a later invitation/migration.
- [ ] Temporarily block the remaining peers' direct SIP/RTP path while retaining their original calls to A. Handoff must fail safely without releasing the originals. Restore access and retry.
- [ ] Temporarily block the room TCP path before leaving. A should remain open, show an error, and retain original connections. Restore reachability and retry. Test a lost acknowledgement during commit separately; expect an in-progress status, not a claim of rollback.
- [ ] Treat power-off/forced-stop as an explicitly unsupported failure scenario; reconnect calls manually. Do not use it as a promised failover test.

## Русский

В этой бета-версии исправлены первое отображение и сохранение фильтров, карточка неизвестного номера и локальное создание контакта. Добавлены меню удаления подключённых участников с подтверждением и проверкой прав создателя, а также поэтапная передача звонка при штатном выходе организатора.

Создатель и текущий владелец аудиомикшера — разные роли. Новый организатор не получает права создателя. В этой бета-версии удаление участников доступно только создателю, который одновременно владеет микшером. После выхода создателя новый администратор не назначается.

Передача требует **1.1.1-beta LAN2 на всех компьютерах** (метка в окне «О программе»), прямого TCP-доступа к каналу комнаты и UDP SIP/RTP между остающимися участниками. Новые соединения идут напрямую на согласованный частный IPv4 и фактический SIP-порт, без АТС. Обычные звонки сохраняют зарегистрированную учётную запись. Старые бета-клиенты не участвуют в новой передаче: сначала обновите всех. Windows может запросить разрешение для частной сети; правила брандмауэра автоматически не добавляются. Обязательное развёртывание Apps Script не требуется. Ожидается короткая пауза при переключении аудио. При ошибке до подтверждения исходные соединения сохраняются и восстанавливаются; при потере подтверждения после принятия решения оставьте QTalk открытым и повторите выход. Приглашение участника нужно сначала завершить или отменить.

**Выключение питания, аварийное завершение процесса и потеря сети организатора не обеспечивают автоматического продолжения конференции.** Локальный микшер исчезает вместе с компьютером. При разрыве сети во время подтверждения возможна частичная передача и ручное восстановление звонков. Номера SIP и каталог используются в модели доверенной локальной сети, без обещания криптографической аутентификации.

Проверка на трёх реальных компьютерах и установка EXE в ходе сборки не выполнялись. Перед установкой закройте QTalk штатно, дождавшись передачи активной конференции. Установщик обновляет обычную установку QTalk; отдельный профиль для бета-версии не создаётся.

Диагностика LAN2: копируйте только `qtalk-*.log` из `%LOCALAPPDATA%/QTalk/logs` с каждого участвующего компьютера, укажите время и номера участников. Журналы содержат внутренние IP и номера; передавайте их только ответственной команде. Пароли, HA1, Authorization, тела SIP и секреты комнаты не записываются. Не собирайте базы ключей, настройки или весь профиль. Размер журналов ограничен четырьмя файлами примерно по 256 КиБ; недоступность записи не прерывает звонок.
